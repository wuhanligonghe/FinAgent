# 提示词注入与输出泄露防护

2026-11-03 接入。核心实现为security.py，默认在主会话、运行中追加输入、辅助模型、Goal判断和独立研究角色模型生效。主会话入口先过滤，模型边界按信任级别标记数据，模型返回后先做输出安全检查，再进入工具执行或事实校验。

## 1. 已知模式输入过滤

NFKC规范化、忽略大小写及部分零宽/双向控制字符后，用正则识别：

- 覆盖指令：忽略上面/之前的系统指令、ignore previous instructions等。
- 伪造角色：system/developer标签、常见模型协议角色标记。
- 提取提示词：显示、打印、复述隐藏system prompt等。
- 凭证外传：读取.env、打印/发送API key或私钥等。

高风险直接请求在主会话注册为真实用户任务、调用模型或选择记忆之前被拦截，不进入任务授权来源。阻断事件仅记录类型、长度与输入摘要。运行中追加输入也会检查。安全术语关键词单独出现时只标记；明确引用后要求解释、检测风险以及部分否定请求允许进入，保留数据身份。正常“忽略上面关于茅台的分析，改查宁德时代”不会仅因关键词而被拒绝。

检索/工具返回及上下文字符串中的高风险指令会隔离，原始证据仍按既有机制保留。MCP工具与参数描述也进行已知模式检查，描述不能授予权限。旧历史中的相同攻击字符串不能通过恢复会话重新获得可执行身份。

## 2. 消息信任边界

真正的System消息用system_instructions分隔符包围，并增加固定的信任边界规则。其他内容以JSON标签区分：

| kind | 含义 |
|---|---|
| user_input | 可在系统规则及宿主权限内执行的用户请求；引文、代码和附件仍是数据 |
| runtime_context | 用户原文来源、任务状态、摘要、记忆等上下文数据 |
| tool_data | 工具返回的不可信资料 |
| host_feedback | 宿主生成的本次校验反馈，不能扩大权限 |

模型输入中的尖括号、&等会转义，防止文本直接闭合分隔符。信任标签由宿主写入，用户在字符串里伪造相同标签不能改变真实role。历史原文和source_id保留用于来源校验，标签作用于发送给模型的副本。工具ID和消息配对保持不变。旧研究适配器中的动态runtime JSON会在受保护模型边界降为用户角色的上下文数据，不作为System指令。

这些标签是模型可见的边界提示，不是模型级隔离机制；工具白名单、路径保护、Schema和授权检查继续是执行边界。

## 3. 输出泄露检测

输出交付、写入正常助手历史和执行模型工具调用前检查：

- 当前注册System Prompt的较长连续片段：去除部分空白和Markdown格式后，默认48字符匹配；命中则扣留输出。它不是语义级泄露判断。
- 已配置模型/角色密钥、指定环境变量中的密钥；支持部分URL编码、Base64、十六进制和空白拆分变体。
- 常见API key、Bearer令牌、私钥块、password/API key/signature等赋值格式。
- 常见邮箱、中国手机号、部分国际电话、身份证、SSN和带明确标签的银行卡号；结构化phone/email等字段也会脱敏。

普通PII和可定位密钥替换为脱敏占位符；系统提示词片段或难以局部清理的命中会扣留整段。含敏感信息的拟执行工具参数直接拦截该批调用，不静默替换参数后继续操作。工具调用前的模型说明及终端工具进度同样经过输出过滤。单条消息被拦截不代表之前已完成的工具操作被回滚。

v3.1 修复内部 ID 的手机号误判：完整 32 / 64 位且含 a-f 字母的十六进制标识符（含已列出的 user_/raw_/result_ 等前缀）内部数字片段不按手机号处理，避免改写来源或产物引用。独立手机号、结构化敏感字段与已配置密钥继续处理；标识符形状仅用于减少此项误报，不授予证据或工具权限。固定 ID 的聊天启动和完整研究回归覆盖该场景，见 [v3.1 更新记录](../requirements/FinSight_v3.1_统一工具注册更新方案.md)。

辅助摘要/记忆、目标判断及研究角色通过相同的受保护模型边界，避免仅保护主模型。模型返回的隐藏推理和签名有不同协议要求；本防护聚焦用户可见正文、工具参数与可见历史，不将签名推理块改写后伪装成有效签名。

## 4. 配置与审计

```toml
[security]
enabled = true
filter_inputs = true
tag_messages = true
detect_prompt_leaks = true
redact_pii = true
min_prompt_fragment_chars = 48
# 可追加服务所用的敏感环境变量名，不在此填写密钥值。
sensitive_env_names = ["FINAGENT_API_KEY", "OPENAI_API_KEY", "ANTHROPIC_API_KEY",
                       "DEEPSEEK_API_KEY", "AWS_SECRET_ACCESS_KEY", "AWS_ACCESS_KEY_ID"]
```

input_security_checked记录命中类型/动作及输入摘要，output_security_filtered记录检测类型和处理动作，不在这些安全事件中回显命中的密钥或PII。受保护回复在正常模型响应/助手历史持久化之前过滤，异常协议的审计消息也做脱敏。

这不是存储加密或旧数据库清理：原始用户输入、Web提交记录、源文档、授权工具结果、历史产物和部分隐藏推理仍可能包含敏感数据。不要据此认为所有内部文件、日志、旧报告或手工维护命令的输出都已脱敏。对这些数据的访问仍须依靠本机权限、已有工作区保护和单独的数据保留策略。

新冻结评测包会绑定security配置；此前固定协议的业务对照/任务回放显式关闭新安全包装，旧冻结结果不代表新增防护后的效果。原候选集分数不是攻击成功率或泄露率。

## 5. 验证与局限

tests/test_security.py使用合成密钥、PII和模型响应，验证直接攻击阻断、引用讨论、Unicode/零宽规避、分隔符伪造、资料隔离、MCP描述污染、提示词泄露、PII脱敏、工具参数外传、恢复历史、辅助模型和目标判断等边界。既有权限和研究回归继续执行。

正则和标签都可能误报或漏报。改写、分片、复杂编码、间接语义攻击、低于长度阈值的提示词片段，以及未覆盖的姓名/住址/电话形式没有通用保证。财务大额数字与手机号可能冲突，规则对明显元/股金额做有限豁免，因此不能将此检测当作完整的PII识别器。无模型攻击基准或独立红队成绩时，不能宣称已免疫注入或泄露率为零。
