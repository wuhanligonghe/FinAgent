## 1. 本轮决策与范围

**普通问答和专项分析由聊天语义决定；深度研究与完整决策由用户显式选择。MacBERT 不再预测分析深度和流程偏好。**

本轮必须同步完成应用路由、权限交接、会话状态、数据合同、数据迁移、模型结构、训练、解码、评估和部署包升级。仅在界面增加按钮，或者只从 JSON 删除两个标签，均不算完成。

本文覆盖旧文档中自然语言自动升级研究、`depth`／`workflow_preference` 训练及相关默认路由条款。既有证据约束、历史截止、预算、取消恢复、质量门、角色独立产物和无实盘交易边界继续有效。不迁移 LangGraph，不更换分析师使用的生成式模型，不引入 OpenFinData，不要求新增 Web 前端。

### 1.1 背景事实

当前应用以 CLI／终端聊天为主要入口。`nlu/parser.py:semantic_route` 仍从模型预测的 depth 和 workflow_preference 决定流程；deep 且非 research_only 会进入完整决策。`tools/delegation.py` 另有研究委托入口，两处必须一起迁移。

当前 MacBERT 使用 10 个分类头和一个 BIO 实体头。独立训练目录已有 2000 条合成候选，训练／验证／测试为 1360／320／320，但只有 65 个语义分组，训练集为 38 组；这些数据尚不能视为独立人工金标。

2026-10-22 核对到的实验 `bootstrap-2000-experimental-v2`，最佳指针指向第 22 轮：验证集完整帧准确率 35.3125%，主意图准确率 78.4375%，流程偏好 Macro-F1 31.2312%；完整决策与仅研究类别的 F1 均为 0。该结论来自 320 条合成验证样本，不是生产效果。数据失衡、否定表达和证券角色识别的问题，不能通过移除两个分类头宣称已经解决。

## 2. 用户模式与实际执行边界

### 2.1 冻结三个用户执行模式

`execution_mode` 为宿主字段，取值如下；它不是 MacBERT 的输入标签或输出字段。

| execution_mode | 用户名称 | 启动方式 | 执行边界 |
|---|---|---|---|
| `chat` | 普通问答与分析 | 默认聊天或普通单次问答 | 模型识别主意图，进行工具查询、概念问答、报告读取或指定维度专项分析 |
| `deep_research` | 深度研究报告 | 用户菜单选择／明确参数 | 分析师研究 → 质量检查 → 多空交替辩论 → 研究经理裁决 → 报告 |
| `full_decision` | 完整研究与决策 | 用户菜单选择／明确参数 | 深度研究报告的阶段 → 交易员方案 → 激进／保守／中性风险讨论 → 投资组合经理最终决策 |

普通聊天中的专项分析仍可复用原研究协调器的分析、有限审阅和综合，但不得调用多空、研究经理、交易员、风险团队或投资组合经理。多维专项请求不因维度数量增加而升级；普通聊天中没有指定维度时，先询问维度，并提供进入显式研究菜单的选项。

**deep_research 是 v2.2 新的阶段边界。** 当前旧 `pipeline=research` 是 v2.0 分析师、审阅和 synthesis，不包含多空辩论；不能把它直接重命名为 deep_research。当前完整决策协调器已有多空和研究经理，但默认继续交易员与风险链，必须新增受控停止边界。

### 2.2 普通聊天的确定行为

| 用户输入／状态 | 必须行为 |
|---|---|
| “分析一下中电鑫龙最近的新闻面” | chat 内新闻专项；不要求用户选择深浅 |
| “只分析基本面和政策”且已有明确对象 | chat 内两个维度专项；不启动辩论 |
| “分析一下中电鑫龙” | 澄清希望了解的维度，可同时展示 `/research` 入口；不得默认五维决策 |
| “深入／全面／仔细分析一下中电鑫龙”但未选模式 | 仍为 chat；没有明确维度则澄清，不以这些词触发研究模式 |
| “全面分析中电鑫龙的新闻”但未选模式 | 仍为新闻专项，显示当前为普通分析；可提供研究菜单入口 |
| “什么是深度研究／多空辩论” | 概念问答，不启动研究 |
| 查看既有报告／追问报告中的含义 | 读取或解释，不重新研究，不升级模式 |
| 模型返回或工具参数声称 execution_mode=full_decision | 拒绝越权，不把模型输出当作用户选择 |

P0 不新增“是否想深度研究”的隐式分类头，也不使用“深入／全面”等关键词或远程大模型代替原 depth 分类。对所有缺维度的股票分析统一提供澄清选项即可。后续可以增加仅用于展示入口的建议能力，但建议不得授权执行。

### 2.3 显式研究配置

用户选择研究入口后，配置至少包括模式、证券、分析维度、截止时间、允许的研究预算和多空轮次；full_decision 另含风险轮次、决策期限、风险偏好和持仓背景。后两项沿用 unspecified／unknown，不从语气猜测。

默认五维必须在配置摘要中明确展示，允许勾选部分维度，至少选一项。研究报告模式不接受风险轮次等仅适用于完整决策的参数。开始前展示模式名称、阶段、股票、维度、截止时间、模型调用上限和已有用量；用户的一次“开始”操作构成最终选择，不额外重复确认。

模式由控件／命令参数确定。自由文本目标不覆盖模式；页面／菜单必须说明流程调整使用模式选项。发现用户目标与已选范围冲突时应要求调整配置，不能声称已满足冲突要求。取消操作始终优先于模式执行。

## 3. 当前终端入口与交互状态

### 3.1 聊天菜单

新增 `/research`，由宿主处理，不送入 MacBERT 或 AgentLoop：

```text
你 > /research
请选择：
1. 深度研究报告（分析师、质量检查、多空辩论、研究经理裁决）
2. 完整研究与决策（另含交易方案、风险讨论、最终决策）
0. 返回普通聊天
选择 > 1
股票 > 中电鑫龙
分析维度 > 全部
确认摘要 > ……
操作 > 开始 / 修改 / 取消
```

有效证券候选序号、模式序号和开始／取消均由当前宿主菜单状态解释。“1”只有在对应有效候选菜单内才有效。配置期间不取财报、不调用研究模型、不创建正式研究任务；名称确认可以进行受限证券查询并计量。退出／超时／取消后不能留下可复用的启动凭据。

研究完成或取消后回到普通聊天；持久化 last_research_id 仅用于报告关联，不意味着以后每句话都处于 full_decision。菜单草稿只作用于当前待启动任务，不作为永久会话偏好。任务运行中通过原有 Ctrl+C 取消，恢复必须使用明确研究 ID 和恢复入口。

### 3.2 CLI

以下是**开发后应提供的命令合同，目前不表示已可执行**：

```bash
python -m finagent research --mode deep_research --symbol 002298.SZ --analysts news fundamentals
python -m finagent research --mode full_decision --symbol 002298.SZ --debate-rounds 2 --risk-rounds 2
python -m finagent run "分析一下中电鑫龙最近的新闻面"
```

普通单次问答沿用现有 run，不新增同义入口。research 子命令是显式研究入口：交互终端缺 --mode 时展示菜单；非交互时返回 MODE_REQUIRED 和合法枚举，不默认 full_decision。明确传入 mode 的一次 CLI 调用即授权，无需交互确认。

旧 --depth／--pipeline 作为新研究入口参数标记弃用。仅旧参数、没有 --mode 的新任务须提示明确选择，不能把旧 research 自动映射成带辩论的新研究报告；同时传 mode 和旧参数须报参数冲突。原有专项 CLI 能力迁移为普通分析入口，并给出迁移说明。读取／恢复历史任务按第 7 节处理，不套用新建任务规则。

### 3.3 统一选择与授权合同

实现宿主创建的 ResearchSelection／ExecutionSelection，至少包含 mode、source（terminal_menu／cli_flag，预留 ui_action）、已确认 symbol、维度、as_of、轮次、预算配置、session 或请求标识以及选择记录 ID。选择记录由真实控件／命令处理器生成；不能允许模型通过自报 source 获得信任。

普通 chat 的 execution_mode 由宿主设为 chat；专项分析的 action=specialist 由 NLU 意图和维度导出。显式深度任务的模式只来自有效选择记录。证券、日期、预算和轮次仍须经过原有类型及业务校验。

旧内部 ResearchRequest.depth／pipeline 若为兼容而保留，只能由宿主根据已选模式和版本生成，不能继续从 NLU 读取。chat 专项可映射至原 specialist＋research；两个新深度模式使用新阶段计划，不能仅靠旧 pipeline 值区分或启动。

宿主范围签名／哈希必须覆盖 execution_mode、scope、阶段边界及选择来源引用。委托工具只能消费宿主登记的本轮请求 ID，并核对证券、截止时间、分析师、模式和预算；工具参数不得创建、升级或修改授权。不得仅修改模型提示词实现隔离；macbert、显式兼容后端、CLI、chat 和 start_stock_research 等入口都必须受相同宿主门控。

显式研究已提供全部结构化参数时，不要求 MacBERT 再次判断 stock_analysis 或预测模式才能开始；其缺失／未合格不应阻断纯结构化入口。若缺少证券等字段且需要解析自由文本，可调用合格 NLU 填充，但低置信度只澄清缺项，不撤销或扩大已选模式。不得用旧正则裁剪公司名作为隐式回退。

## 4. 研究 Harness 与产物

### 4.1 阶段计划

为新任务建立 workflow_version=2.2 的版本化合同及阶段计划。模式明确写入 scope，不能仅依赖某个配置开关或最终报告标题。

| 阶段 | chat 专项 | deep_research | full_decision |
|---|---|---|---|
| 所选分析师与原有专项审阅综合 | 是 | 复用分析能力 | 复用分析能力 |
| v2.1 质量门及有限补查收口 | 不新增决策质量链 | 是 | 是 |
| 多头／空头严格交替 | 否 | 是 | 是 |
| 研究经理裁决 | 否 | 是，作为最后领域判断 | 是 |
| 交易员、三方风险、投资组合经理 | 否 | 否 | 是 |

深度研究报告模式的计划中不创建交易员、风险和投资组合经理任务；不能把这些节点设为“失败／跳过”后才宣布流程完成。完成条件为本模式必需节点完成，不要求 portfolio_manager 产物，也不由旧 synthesis 冒充研究经理裁决。

### 4.2 报告、预算与恢复

deep_research 报告包含各维度发现、证据质量、双方论点及回应、研究经理裁决、分歧、未决问题和来源；没有执行的交易／风险阶段不得出现已完成结论。full_decision 保持 v2.1 完整角色产物和报告要求。报告名称、状态页、过程查看和导出都显示实际模式及版本。

预算按模式明确配置；deep_research 不预留或消耗交易员／风险角色额度，full_decision 继续计量所有阶段。具体额度由实施时对现有配置核对后写入运行说明，不以减少模型头数推算研究成本。失败、证据不足、补查、取消和恢复沿用原 Harness 限制，不为获得完整报告反复重置预算。

已启动任务的模式不可原地修改。升级到 full_decision 必须再次显式选择并创建关联的新任务，保留 parent_research_id；跨任务复用材料须重新校验时间、证券、范围和证据授权，并分别展示原任务与新增任务成本，不得伪装成原预算未消耗。P0 可以暂不复用，完整记录关联即可。

## 5. MacBERT 新合同：nlu22.1

### 5.1 移除与保留

| 内容 | v2.2 要求 |
|---|---|
| depth、workflow_preference | 从模型标签、分类头、输出、阈值、损失、置信度准入、校准和评估中移除 |
| task_type | 保留现有 7 类，状态／报告／恢复不在本轮顺带合并 |
| dialogue_act | 保留现有 7 类，继续处理追问、纠正、换股、澄清、取消 |
| entity_binding | 保留现有 4 类及上下文指代规则 |
| dimension_state | 保留五维各自 include／exclude／unspecified，不能简化掉排除含义 |
| entities | 保留 10 类实体、证券三角色和原文 offsets；BIO 枚举本轮不改 |
| 执行模式 | 移至宿主合同，不新增同义分类头，不混入 task_type |

新架构固定为共享 MacBERT + **8 个分类头（主意图、对话动作、实体绑定、5 维状态）+ 1 个 BIO 头**。不是仅剩一个意图分类器，也不承诺通过这次减少两个头就解决所有效果问题。

schema_version=nlu22.1，architecture=macbert_joint_v2，preprocessing=context_pair_v2，伴随包 finagent-macbert-nlu 升级至 0.2.0；FinAgent 产品包版本单独管理。模型包、伴随包和应用兼容矩阵一并升级。labels.json、preprocessing.json、配置、状态哈希和包 manifest 都须记录对应版本。旧头名出现在新模型配置或阈值中应报错，禁止忽略后继续使用。

### 5.3 解码与宿主分流

解码器删除 conflicting_workflow 及任何依赖被移除头的准入检查。模型级准入保留置信度、BIO、证券角色与实体绑定一致性；chat 股票分析是否缺维度、用户是否选择研究模式，由宿主根据当前入口判断。

不能把 execution_mode 传回模型让模型确认，也不能将菜单选择和模型模式预测相互投票。NLU 接收的必要语义上下文不再含旧 depth 字段；dimensions 若来自当前有效菜单／待澄清请求可保留，但须记录其来源。新语义结果不得夹带 mode、pipeline、depth、workflow_preference 等执行控制字段。

普通聊天的证券身份继续由数据服务确认；entity_binding 不能替代身份解析。具体日期、最近几天、报告期等仍由实体片段与确定性归一化实现，不恢复整句正则扫描。全未指定维度不能自动等价于五维；显式研究菜单的默认五维由用户可见配置提供。

## 6. 数据集、训练和评估同步迁移

### 6.1 原始语料保留与迁移产物

training 目录继续独立上传，不依赖 FinAgent 源码、数据库、聊天记录、持仓或密钥。不得覆盖 bootstrap_500_v1、expansion_1500_v1、bootstrap_2000_v1 和既有 outputs。

建议提供如下可复现实验起点，写入新 `configs/3090_nlu22.yaml`，实现后按真实验证结果调整；它不是已验证最优参数：

| 参数 | 初始配置 |
|---|---|
| max_length | 128，当前话轮不静默截断 |
| batch_size／gradient_accumulation | 16／2 |
| 编码器／任务头学习率 | 2e-5／1e-4 |

首版实体损失沿用现有 CE，另外记录各 BIO 标签支持和实体跨度指标，不把 token 准确率作为实体质量。任务损失系数支持配置，默认对 8 个分类头和实体头各为 1。相同划分、seed、训练预算下至少比较“新合同不加权”和“新合同加权”两次实验；若对旧十头模型作因果对照，须统一其余配置，不用现有高学习率实验直接证明删除两头的收益。

### 6.4 指标与最佳模型选择

必须同时报告：主意图 accuracy／Macro-F1、每个分类头及每类 F1／支持／混淆、每维 include 和 exclude 的 precision／recall／F1、五维完全匹配率、证券集合完全匹配、角色化实体跨度 F1、完整语义帧、接受准确率和覆盖率。完整语义帧只含新合同的 8 个分类头及实体，字段集合写入报告。

冻结下列统计口径，旧版不同口径指标只能另外命名保留，不可直接套用发布门槛：

- 完整语义帧：8 个分类头均有 gold、entities 已完整标注的样本才进分母，逐头相等且实体集合完全相等才算正确；entities=[] 是完整的无实体标注，entities 缺失不是。缺标 -100 不当作正确、不进完整帧分母，报告排除样本数及原因。
- 实体键为 `(type, role, start, end)`，非证券 role 为空；实体跨度 F1 对完整标注样本按此键计算 micro-F1，边界相同但角色不同仍算错误。证券集合包含 COMPANY／STOCK_CODE 的 target、excluded、background；以 gold 含证券的样本为分母，gold 与预测证券集合严格相等才正确，额外提取也算错。另报无证券样本的证券误提取率。
- 五维完全匹配只统计五维 gold 齐全的样本；主意图 accuracy 和每头指标仅统计该字段有 gold 的样本。
- 发布准入评测集必须有完整语义及 expected_admission。接受准确率为“预测 accept、gold expected_admission=accept 且完整语义帧正确”的样本数除以所有预测 accept 的样本数；把本应 clarify／reject 的输入接受也算错误。覆盖率为 gold 应 accept 中预测 accept 的比例；另报正确自动处理比例，分子还须完整帧正确。零分母记为 null，不能通过相应发布门槛。
- 例如 100 条应接受输入中预测接受 60 条、其中 54 条全帧正确，另错误接受 5 条应澄清输入，则接受准确率=54/65，覆盖率=60/100，正确自动处理比例=54/100。

新增固定验证选择指标：

```text
val_selection_score =
    0.25 * task_type_macro_f1
  + 0.35 * mean(five_dimension_macro_f1)
  + 0.15 * dialogue_act_macro_f1
  + 0.10 * entity_binding_macro_f1
  + 0.15 * entity_span_f1
```

各头 Macro-F1 对冻结枚举全部类别取均值；缺支持类别仍显式报告，不因本轮预测情况改变分母。缺支持的诊断集可计算选择分，但不能晋级发布。按此分数选 best 和早停，同分优先完整语义帧，再同分取较早轮次。完整语义帧作为独立端到端约束，不能被加权分替代。

不以新完整帧分数直接对比旧完整帧并宣称提升，因为新指标少了两个必答字段。需要对旧预测投影到相同字段集合，标记 shared_field_exact_match；旧预测缺失时明确记为不可比。校准仅用 validation，测试集不参与阈值和配方选择；任何反复用于调参的集合记为开发集。

### 6.5 正式上线目标与候选诊断

以下为待实现的发布门槛，不是当前模型成绩：主意图 Macro-F1 ≥0.90；五维各自 Macro-F1 ≥0.85，且每维 include／exclude F1 ≥0.80；dialogue_act、entity_binding Macro-F1 各 ≥0.85；角色化 entity_span_f1 ≥0.90；证券集合完全匹配 ≥0.95；新完整语义帧 ≥0.80；接受请求的完整帧正确率 ≥0.95、覆盖率 ≥0.70。全部在至少 300 条独立人工核验样本及上述类别支持约束下报告。

阈值是业务发布目标，不保证现有候选数据可以达成。不得为了发布自动降低门槛、删掉难例或把待审候选视为人工数据。训练、诊断导出、正式发布候选分别记录；未达标仍可交付工程和诊断模型，但不能默认替换生产 NLU。模型缺失时保留结构化研究入口、帮助和报告命令，普通自然语言给出明确缺模型提示，不隐式退回正则或远程模型。

跨平台继续使用同一伴随包和模型清单，进行服务器 GPU 与本地 CPU 的固定输入一致性及性能检查；保留旧版数值容差和 P95≤500ms 目标，硬件与线程数必须随报告记录，不能用随机小编码器结果替代 MacBERT 实测。
