# 金融Agent业务对照实验

这套实验补充业务结果证据，不用单元测试数量、脚本回放通过率替代模型效果。默认 `prepare` 不请求模型；`run` 才调用已配置模型。全套禁用新增和恢复独立深度研究。

## 三组对照与可解释边界

| 方案 | 输入/能力 | 回答的问题 |
| --- | --- | --- |
| direct | 同一模型，内联读取相同的原始财报表格，无工具 | 直接模型能否完成任务，以及成本多大 |
| agent_no_task | 真实SessionHost，金融工具和原有会话上下文；移除任务框架工具、提示、上下文和强制检查 | 任务表示模块的消融基线 |
| agent_full | 同一SessionHost和金融工具，启用任务框架 | 新增任务表示模块的收益与开销 |

金融工具限定为实体解析、范围解析、原文检索/读取、受限计算、澄清；两种Agent之间只增加/移除任务框架相关能力。记忆、NLU建议、子Agent、后台研究在三组中均不参与。默认两种Agent都用同一个关键词检索策略。

直接模型一次收到全部可用原始表格，Agent按需检索同一原文包，属于端到端方案对照；不能将这组差异全部归因于某一个工具。任务表示的因果讨论应以两种Agent的配对结果为主。此实验是受限金融问答，不代表完整产品、开放网络或长篇研究质量。

## 数据与留出规则

- 候选语料：`src/finagent/resources/business_benchmark.json`，48组、69轮。
- 开发集30组、留出集18组；公司与对话组不交叉；检索查询原文也不跨集合。
- 覆盖事实查询、年份更正、公司切换、利润澄清、公司比较、同比、母公司/合并更正、季度口径、资料缺失和排除项。
- 金额为完全虚构的合成数据，按公司、年份、合并范围、累计/单季分别变化。真实文档入库器校验原始单元格、期间、单位和快照；每个实验case单独建库，缺失样例不会借用其他case的资料。
- 这些是开发者编写的候选标签，不是已经完成独立人工验收的数据。当前未运行留出集效果测试。

留出集 `prepare` 只生成原文和标签审核材料，不计算检索效果；真实运行必须提供运行前人工审核文件。模型输入不包含gold、脚本动作或答案标签，工作区/会话ID经过匿名化，避免从“利润澄清”等case名称泄漏任务类型。

## 先冻结，再运行

```bash
.venv/bin/python scripts/run_business_experiments.py prepare \
  --output .finagent/business_experiments/my_development_plan
```

生成的文件包括：

| 文件 | 用途 |
| --- | --- |
| manifest.json | 推理前冻结的源码、数据、合同摘要；模型、预算、工具、执行顺序与统计方法 |
| implementation/finagent/ | 推理时的包源码快照，摘要与清单一致，不包含本地.env或数据目录 |
| dataset_snapshot.json | 完整冻结标签快照，不发给模型 |
| review_template.json | 人工审核登记，默认pending，不自动填写approved |
| review_answers.json / review_sources.json | 展开后的数值、原始单元格依据与每case可见资料范围 |
| review_data/ | 实际合成HTML原文和验证后的资料库 |
| retrieval.json | 开发集离线检索对照；留出准备阶段保持未运行 |

审核者应检查原话、继承和更正、财务口径、期望动作与原始单元格，填写审核者、带时区时间和approved。标签错误先修订数据并重新冻结，旧审核摘要会失效。不能把模型生成或开发者自检伪装成人工独立审核。

留出集准备示例：

```bash
.venv/bin/python scripts/run_business_experiments.py prepare --split holdout \
  --output .finagent/business_experiments/holdout_review
```

## 小规模真实模型对照

```bash
.venv/bin/python scripts/run_business_experiments.py run \
  --case development_600519_lookup \
  --case development_600519_year_correction \
  --case development_600519_profit_clarification \
  --max-model-calls 60 --soft-token-limit 400000 \
  --output .finagent/business_experiments/my_pilot
```

默认三种方案、一次重复。`--arms`可选方案，`--repeats`设置重复。先根据prepare的任务矩阵确认预算，再安排完整实验；默认72次调用上限可能无法跑完整开发集，提前停止会明确显示覆盖不足。

源文件、提示、模型名称和工具配置固定；case按固定种子打乱，并在每个case内随机安排方案顺序。种子只控制执行顺序和bootstrap，当前模型适配器使用服务商默认采样参数，不保证API输出确定性，也无法证明服务商后台权重未变化。

所有调用共用硬调用上限，失败请求也计数。token软上限在响应返回usage后检查，最后一个响应可能超出该值；缺失usage另计数，硬调用上限仍生效。记录输入/输出token、调用、逐轮耗时、错误与重试，不根据未确认的单价推算真实费用。

`requests/call_NNNNN.json`保存每次调用的消息、工具schema和超时，供复核真实输入。它不含HTTP鉴权头；公开展示时使用精简trace，不直接发布完整模型上下文。首次pilot早于这项输入/源码归档完善，只有输入数据、输出记录和源码摘要，不声称可逐字复现原推理环境。

## 评分定义

统一输出合同只用于实验，不改变产品默认自然语言输出。模型给出动作、解释后的请求、数值主张与原文定位。

| 指标 | 定义 |
| --- | --- |
| 对话成功率 | 每一轮动作、请求字段、必需数值、引用和运行状态均通过 |
| 字段准确率 | 公司、期间、指标、合并范围、累计/单季、币种、展示单位及排除项逐字段比较 |
| 数值召回 | 必需数值中，公司/期间/口径正确且数值匹配的比例；缺失答案不计正确 |
| 引用支持率 | 数值确实被所引原始表格/单元格支持；Agent还必须实际见到该来源 |
| 无依据结构化数字率 | claims中数值错误或没有正确可见引用支持的比例 |
| 正文金额审计 | 检查带金额/百分比单位的正文数字；分别记录未列入claims、没有可见来源支持的金额 |
| 输出合同完整率 | JSON合同有效，且正文显式金额均进入claims；自然澄清可能满足业务但不满足JSON合同 |
| P50/P95、token | 按实际执行轮次计量，未执行轮次不以0秒拉低延迟 |

同比必须有本期、上年同期两份原文，使用确定性公式核对。重复主张、错币种、错公司、错期间、错口径、伪造定位、未来材料都不能拿到正确分。需要的字段/数值在格式失败或运行失败时仍留在分母。未开始的运行另显示覆盖不足，禁止只取成功样例。

正文出现正确但未声明的对照金额，是合同完整性问题，不自动认定为编造。无单位数字、正文中的公司/期间归属和自由文本语义仍需人工复核，输出的 `prediction_review_template.json` 用于逐答案审阅。

## 统计、报告与简历表述

每个对话在不同方案间配对；重复先在同一对话内平均，再按对话ID进行bootstrap，避免把同一对话的多轮当独立样本。报告百分点差值与描述性95%区间。小样本或全相同差值可能得到退化区间，不能据此证明等效或泛化。

报告有总表、分类别指标、CSV、逐轮错误和来源检查。效果型简历表述的项目门槛为：完整18组留出、运行前标签人工审核、至少3次重复、三种对照齐全、运行矩阵完整。该门槛不是通用统计充分性保证。只有配对区间支持正向变化时，报告才标记可讨论“提升”；无正向证据应如实报告持平或退化。

准备阶段和开发试跑只生成工程能力表述，例如：

> 构建覆盖48组、69轮候选对话的金融Agent评测框架，支持3种方案对照、数值与证据核验、检索对照及token/延迟追踪。

不能把507项既有单元测试、脚本回放通过或合成开发样例结果写成真实金融场景准确率。

## 零模型调用重新评分

```bash
.venv/bin/python scripts/run_business_experiments.py analyze \
  --input .finagent/business_experiments_v1/live_pilot \
  --output .finagent/business_experiments/my_new_analysis
```

它读取原始回答、实际可见来源和冻结标签，验证数据摘要与原始单元格，生成独立分析目录。原推理清单、原报告和JSONL保持不变；`analysis_manifest.json`明确记录推理版/评分版源码与posthoc分析。无需重新请求模型。

## 检索对照

比较现有“关键词+已有财务概念同义词”评分与“BM25+开发期扩展词”。两种方法共享公司、报告期、截止时间和合并范围过滤。相关单元是包含目标指标的原始表格，报告Recall@1/3/5、MRR、nDCG@5和耗时。

该增强方法是稀疏词法方法，没有使用向量模型或神经重排。开发集查询与扩展词均由开发阶段编写，其高分只说明本候选语料上的结果，不能冒充独立泛化提升。默认聊天检索实现保持原样；实验使用隔离的检索策略覆盖。
