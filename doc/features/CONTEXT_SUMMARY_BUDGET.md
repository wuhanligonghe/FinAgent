# 历史摘要预算与回读去重

[返回功能目录](README.md)

2026-11-18：针对同一请求反复触发历史摘要的问题，减少重复状态输入，为摘要单独配置较短的调用预算，并修正主会话的证据回读定位。

## 已确认的慢点

同一会话两次真实查询的摘要分别调用 8 次、9 次，累计耗时 146.233 秒、165.674 秒；`read_evidence` 本地读取本身合计仅 0.022 秒、0.047 秒。旧实现每次主循环准备上下文时都检查压力，历史运行状态快照不断累加，失败后也没有摘要专用的请求次数和冷却限制。

来源：`.finagent/checks/latest_run_timing_20261118/analysis.md` 与同目录的 `timing_breakdown.json`。未返回 usage 的约 20 秒调用与超时相符，但旧记录不足以确认每次的具体异常。

## 当前行为

1. 模型工作历史只保留最新 `runtime_context`。旧的派生状态快照不再逐轮累积；用户原话、助手和工具消息仍按原有规则保留，完整状态快照继续追加到 transcript 审计记录。
2. 先清理重复快照，再按历史字符预算或消息数判断是否需要压缩。字符压力下按约 60% 的目标容量选取完整消息组，保留最近至少两个组，助手调用与工具返回始终配对。原先“8 个已完成用户轮次后尝试摘要、保留最近 3 个用户轮次”的周期策略仍适用。
3. 同一次主请求及共享账本的子任务共用摘要预算。失败、格式无效和成功均计入次数和耗时；相同历史不在本次请求中重复尝试，两次调用至少间隔 4 次主循环准备检查。这里的冷却轮次不是用户发消息的次数。
4. 摘要使用原有模型和连接，独立设置较小输出及关闭思考参数。主模型原有参数不被改写。提示词要求 JSON 不超过 1600 字符，宿主同时检查长度、结构和来源 ID；来源存在不代表摘要语义必然正确。
5. 无摘要或预算用完时，完整原文先归档，保留当前用户要求、有效约束、TODO、范围约束及原文定位；需要历史细节时再搜索或回读。归档后必要历史仍超出上限则返回 `CONTEXT_LENGTH`，不会静默丢掉必要用户要求或发送超限历史。
6. 超长工具错误在模型可见的失败记录里也只提供 500 字符预览及完整原文路径。完整错误仍保存在持久诊断状态，避免正文虽已转存，却又通过状态快照注入整段错误。

历史的 `context_chars` 是字符预算，检查对象为工作消息历史；不等于供应商 token 上下文限制，也不包含另加的静态系统指令与工具 schema。

## 配置

`finagent.toml` 中的 `[context_summary]`：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `max_calls` | 2 | 每次请求最多摘要尝试次数，0 表示不调用摘要模型 |
| `cooldown_turns` | 4 | 两次尝试间的主循环检查间隔 |
| `timeout_seconds` | 6 | 单次 HTTP 调用超时配置 |
| `total_seconds` | 12 | 累计摘要耗时预算；下一次调用还受剩余预算限制 |
| `max_output_tokens` | 1200 | 摘要模型输出 token 上限 |
| `max_chars` | 1600 | 模型返回摘要 JSON 的字符上限 |
| `target_ratio` | 0.6 | 字符压力压缩后的历史容量目标比例 |
| `disable_thinking` | true | 摘要请求发送 `thinking.type=disabled` |

总预算按实际耗时记账；HTTP 库的超时语义不等于可强制打断任意网络调用的绝对墙钟上限。预算、失败原因和跳过原因通过 `context_summary_attempt` 事件记录。主模型、工具和总执行预算仍同时生效。

关闭思考参数适配当前 DeepSeek 兼容服务；协议依据：[DeepSeek Anthropic API](https://api-docs.deepseek.com/guides/anthropic_api/)。迁移到不支持该参数的供应商时可设置 `disable_thinking=false`。

删除旧状态快照会改变其后部分的消息前缀。静态系统与工具定义仍保持既有策略，但不能据此保证每轮缓存命中；输入膨胀和缓存收益之间需要用真实请求量测。见[工具渐进披露](TOOL_DISCOVERY.md)。

## 原文回读

`read_evidence` 的分页坐标始终属于原始证据全文。误传上一次回读结果 ID 时，宿主在本任务授权范围内追溯原始 ID，返回 `data.evidence_id`、`requested_evidence_id`、`offset_basis` 和必要的 `redirected_from`。模型继续使用原始 ID 和 `next_offset`，避免把已经转义的回读 Observation 包装当成新原文再读一遍。

宿主合并已读字符区间。只有原文仍在当前工作历史、且有匹配的真实 `read_evidence` 调用和工具返回时，重复区间才不再注入；返回 `EVIDENCE_ALREADY_READ` 和后续位置。历史归档后允许重新读取原文。其他工具伪装成回读结果不能标记某段证据已读；每次追溯仍检查本任务登记权限。

`read_output` 同样跳过当前可见的已读前缀，返回实际 `offset`、`requested_offset` 及 `next_offset`；完全重复时返回 `OUTPUT_ALREADY_READ`。原文已离开上下文后可再次回读。文件边界与权限检查保留，工具大结果仍使用原文预览加全文转存，不生成大结果摘要。

## 验证与限度

- `tests/test_summary_efficiency.py` 覆盖次数、冷却、总耗时、取消、摘要请求参数隔离、原文回读和授权、当前可见区间去重、归档后重读，以及状态审计保留。
- 相关定向回归 240 项通过；完整后端回归 924 项通过，耗时 220.657 秒。模型及行情测试主要使用合成夹具，不能视为真实金融任务的准确率或生产验收。
- 使用真实旧归档进行一次当前模型的摘要实测：3.585 秒，生成并接受 1470 字符摘要，未改动原历史。只证明这一次调用通过结构和来源校验，不证明语义准确率或稳定延迟。
- 固定旧 transcript 的主模型动作和工具结果，用合成摘要重放上下文策略：两次请求各 2 次摘要尝试，主模型调用前历史峰值为 57149、59890 字符。原 transcript 未改动。这是策略回放，不是新模型的端到端耗时或答案质量评估。
