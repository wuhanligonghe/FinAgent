# 主对话与独立研究衔接

深度研究继续独立运行，在主对话中发起、观察进度、读取报告及承接追问。独立命令入口保留。对话中的使用方法集中于 `skills/deep-research/SKILL.md`；多空、经理与风险角色方法位于 `research/prompts/`，由研究执行器直接加载。

## 使用方式

1. 正常查询或讨论一家公司。
2. 直接输入“给刚才这家公司做一份深度研究报告，重点分析现金流质量”。主模型发起独立后台任务，不要求重新输入股票代码和命令。
3. 聊天显示启动信息、独立预算和阶段进度；可以继续讨论其他公司。
4. 研究完成后，所属会话收到通知。主模型使用通知中的研究ID读取实际报告，给出摘要、依据、缺口和报告位置。
5. 继续问“报告里为什么这样判断”“这个结论有什么证据”。读取报告及已授权证据，不重新启动研究。

简短命令：

```text
/research 分析现金流质量
/research-list
/research-status
/research-report
/research-status work_...
/research-report work_...
```

完整CLI、两种研究模式及恢复命令见 [运行说明](../guides/RUNNING.md)。

## 上下文与任务边界

- 发起时冻结当前公司、主对话截止时间、有效用户约束、报告期等范围条件和市场窗口；主模型提炼的目标不能替代原始用户要求。
- 工作记录保存交接快照；研究创建后写入独立目录的 `conversation_handoff.json`。分析执行器核对研究选择、公司、截止与会话后继承结构化范围条件。
- 不将主模型的自由文本结论当作已核验事实，也不因交接中出现证据ID就自动授予研究读取权限。
- 切换主对话公司、修改后续聊天约束，不修改已经冻结的研究。主模型与研究使用独立预算和取消信号。
- 目前独立公司研究不接收指数、行业或概念板块；不能将它们替换成某只股票执行。

## 发起、进度与报告

`start_deep_research` 只开放给主会话的明确用户请求。参数包含最新真实用户消息的 `source_id` 与逐字 `request_quote`。宿主校验来源及明确启动表达；模糊深入、否定、假设、引用材料、功能咨询、报告解释和后台通知不作为新的启动依据。`full_decision` 需要用户明确要求完整决策链。

这不是关键词路由：普通对话先由主模型理解，只有它调用启动工具时才校验研究启动边界。无需额外的常规确认轮次；对象或范围存在实质歧义时才澄清。

同一真实用户请求的重复调用复用已有工作，避免模型重试或会话恢复时重复启动。

`list_research` 返回本会话任务与关联报告；`research_status` 接受研究ID或工作ID，省略则选择最近发起的研究。实际研究ID在任务创建时关联，无需等整份报告完成。进度与完成状态写入持久记录；进度展示失败不改变研究结果。启动失败保留具体错误，不宣称已经生成报告。

`read_research_report` 接受研究ID或工作ID；省略时沿用刚读过的报告，否则选择最近研究。读取另一份历史报告不会改变主对话当前公司或截止时间。完成通知必须明确指定对应研究ID，避免与用户刚读过的另一份报告混淆。

报告返回原范围、报告位置、可采用的证据结果及分页信息；模型每次最多读12000字符。原始证据按当前截止时间重新检查，旧行情继续标记失效。报告的生成完成不代表其内容完整，也不代表最新市场状态已核验。

## 验证

`tests/test_research_chat.py` 使用脚本模型和合成金融来源，覆盖自然语言工具调用、误启动拒绝、深度与完整决策区别、用户约束及历史截止继承、独立后台运行、重复启动防护、进度、自动摘要衔接、报告分页与追问、跨会话隔离、取消、失败原因和重启关联。

其中一项实际经过研究协调器、分析执行器、多空研究与报告生成链路，验证交接文件及范围条件；不访问真实模型或金融来源。测试不证明所有真实模型都能正确理解自然语言，也不代表金融报告质量已通过人工验收。
