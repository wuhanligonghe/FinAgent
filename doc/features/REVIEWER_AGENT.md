# 独立证据审核 Agent

2026-11-18 更新：生产 `[fact_check.review].backend="main_model"`、`agentic=true`。独立 ReviewerRuntime 使用与主模型相同的模型、API 地址、协议、密钥和代理配置，不再向本地 Ollama 发起审核请求。提示词、四维判定、只读取证、引用校验及共享预算沿用现有实现。

## 执行链路

用户请求与有效约束、完整草稿 → 完整证据登记与来源检查 → 正文去重 → 紧凑字段视图与分页目录 → Reviewer 只读搜索/读取 → 四维判定 → 主模型修正或交付。

`ReviewerRuntime` 复用 `AgentKernel`，不实例化拥有业务写操作的 SessionHost 子任务。`MainReviewModel` 为每次审核建立独立的 `CompatibleChatModel` 连接，从主模型配置复制模型身份和凭据；不会复用主模型的对话或推理。审核上下文不继承主模型推理、TODO、自评或模型生成的会话摘要；用户原始需求、有效约束和执行截止时间继续保留。所有工具数据经现有 SecurityGuard 标记为不可信资料。

接口支持原生工具调用与原有 `{action, arguments}` JSON。模型直接返回完整提交参数 JSON 时，只将其包装为 `submit_review` 动作，不补字段、不改变判定；仍须通过既有结构、四维检查和原文引用校验。多个原生只读取证调用由内核顺序执行，每个分别扣取证/工具预算；提交结论必须独立调用，不能与读取混合。没有扩大工具范围或预算。

审查只披露自身四个工具，使用原有 4096 输出 token 预算与关闭思考设置；主模型参数不被修改。服务不可用、截断、无效输出或未完成审核均不放行草稿，也不会自动回退到本地 Ollama。

工具仅包含：

- `list_review_evidence(offset, limit)`：列出本次允许使用的证据、相关版本、字段与集合条数。初始目录最多展示20条，其余通过分页加载。
- `read_review_evidence(evidence_id, path, offset, limit)`：按 JSON Pointer 读取规范结果字段；offset/limit 是从0开始的字符范围。path 默认 `/body`，默认至多1200字符、单次最多6000字符，返回总量、下一页位置和覆盖范围。读取首页且未覆盖全文时另附末尾最多200字符预览，明确中段未读；两段均计入取证预算并记录实际位置。
- `search_review_evidence(evidence_id, query, path, offset, max_hits)`：单关键词字面搜索；空格分隔的多个关键词取所选字段内的交集，不要求相邻或同序。返回命中片段及位置。
- `submit_review`：提交结构化判定，不改变证据或放行规则。

审核工具不接受文件路径、URL或目录外结果ID，不开放 Shell、写文件、MCP、外部行情查询或权限修改。审核模型生成任意其他工具名都会被内核拒绝。

## 证据与覆盖

原始响应、完整 Observation 和完整审核证据包继续保存。Agent 模式下，证据正文总量超过旧 `max_evidence_chars` 不会被裁掉后标记成缺证；容量控制施加在实际发送的目录、字段视图、取证结果和协议上。无法读取、未登记快照或非法时间等真实来源问题仍阻断审核。

同正文且工具、公司、数据时间、币种单位、价格口径、状态、警告和来源版本一致的结果共用正文，保留所有原始 result_id、获取记录和快照。变化的数值、期间、单位、口径、来源版本不合并。引用校验同时检查本次实际加载的原文及所引用ID的具体来源，不能将一个观测的获取时间挂到另一个ID上。

字段视图由代码逐字提取，不调用摘要模型。优先提供小型报价和程序计算结果；日线大数组等保留定位入口，其他字段按预算加载。目录注明正文是否完整加载、集合条数和相关记录。审核器不能将“未加载”当作“原文不存在”；只读前缀后若要作缺证判断，必须继续搜索定位或读取完整字段。补查反馈会列出尚未覆盖的具体证据ID和JSON Pointer，避免模型对无关记录重复搜索。补查要求未满足时，下一次动作schema暂不提供submit_review；成功读取或搜索所需字段后才恢复提交，防止模型重复提交同一缺证结论。该覆盖检查不替代模型对语义相关性及冲突的判断。

## 判定与修正

每次提交均覆盖四个维度：事实支持、范围与单位、推理、要求与限制的完整性。输出包括 `checks`、`complete`、`verdict`、问题的草稿原文位置、类型、原因、修复建议和原文引用。

- `pass`：各必需维度通过，没有未解决取证问题；含外部事实时须有已加载原文的有效引用。
- `revise`：指向草稿中的实际问题并给出可执行修复意见。正常舍入、免责声明、没有逐句展示内部ID不单独构成拒绝原因。
- `unable_to_verify`：明确不能完成审核，可设置 `complete=false`；主模型草稿不交付。

引用由代码检查ID、来源和原文一致性；`contradicted` 必须引用实际读取的相矛盾证据。可验证的算术由原有受控计算工具执行，并保留输入结果ID与公式供回查。语义支持、归因、预测确定性和重要遗漏由模型判断。约束正确不证明语义判断必然正确，也不证明供应商数据真实。

## 共享预算与审计

每个主请求持有一个 ReviewBudget。取证、协议纠正及主模型修正后的再次审核累计使用同一预算，不能通过新建审核上下文重置次数。全部模型/工具调用也计入主请求 Ledger；取消和主请求预算仍优先生效。

```toml
[fact_check.review]
enabled = true
agentic = true
backend = "main_model"
timeout_seconds = 90
context_tokens = 131072
output_tokens = 4096
max_input_chars = 12000
max_model_calls = 6
max_tool_calls = 14
initial_evidence_chars = 16000
max_read_chars = 24000
max_read_per_call = 6000
protocol_retries = 1
max_retrieval_calls = 4
max_no_progress_calls = 2
```

90秒为各次审核实际耗时之和，主模型修正耗时另外受主请求总预算限制。读取缓存按源内容指纹和参数区分，重复读取不重复扣取证字符量，但仍消耗工具调用预算。输入按包含消息与动作schema的保守UTF-8字节上界检查，并预留输出空间；这不是精确token计数。实际token由模型返回并记录。

`reviews/<id>.json` 保存完整草稿、源证据包、事件、加载位置、别名、判定及前后预算；主会话事件保存审核步骤和预算摘要，失败同样归档。区分证据来源错误、上下文容量不足、预算耗尽、模型不可用、输出协议无效和未能核实。

`main_model` 自动继承 `[model]` 和 `FINAGENT_MODEL`、`FINAGENT_BASE_URL`、现有模型密钥及代理设置，不需要复制密钥。`FINAGENT_ANSWER_REVIEW_MODEL` / `ENDPOINT` 仅用于显式 `ollama` 后端；不能覆盖 `main_model` 的模型身份。`FINAGENT_ANSWER_REVIEW_BACKEND` 可显式覆盖后端。

旧固定请求 `agentic=false` 仅保留在显式 `backend="ollama"` 兼容模式；该模式需另设 `endpoint` 和 `model`。`main_model` 要求启用独立 Agent。旧 `max_evidence_chars`、`max_evidence_results` 仅在固定请求模式控制全文审核包。

## 2026-11-18：审核上下文去重与补查控制

每轮模型输入改为规则、完整草稿、目录、合并后的 `evidence_memory`、搜索覆盖记录和 `last_feedback`。不再将原始 assistant/tool 历史逐轮重放，也不再在输入和输出 Schema 中重复展开草稿片段、候选引用原文。输出保留结构约束；引用仍由代码检查本次已读范围、原始证据ID及逐字一致性，省略号拼接或引用未读内容会拒绝。旧固定请求兼容模式保持原协议。

`ReviewEvidenceMemory` 按原始证据ID和JSON Pointer记录精确字符区间；同字段重叠、相邻区间合并，有缺口则保持分段。完整父字段已加载时，不重复发送其子字段。片段可合并后进行跨页引用，只有确实覆盖完整字段才解除分页不完整状态。它是代码维护的原文集合，不调用摘要模型。完整动作、工具结果和加载位置仍保留在审计文件中。

新增 `max_retrieval_calls=4`：目录、搜索、读取在同一主请求及修正后的审核间累计计数，缓存命中也计数。新增 `max_no_progress_calls=2`：连续两次没有新增原文、搜索覆盖或目录信息时，以 `ANSWER_REVIEW_NO_PROGRESS` 停止。新搜索即便没有命中也可提供检索覆盖，但不同搜索仍受累计4次上限约束，不能靠换关键词无限延长。失败不自动放行草稿。最近反馈包含原动作参数、下一页位置及是否有信息增量。

上述早期验证使用 Ollama 每次提交完整 messages 的接口；当前后端已切换为主模型 API。每轮仍提交必要状态，不依赖服务端有状态追加协议。原大结果预览与转存机制保持现有配置。按需回读仍有成本，实际累计 token 必须以调用记录测量，不能只用字符量或上下文窗口估算。

## 2026-11-18：修复手写引文导致的审核拒绝

审核模型的 `citations` 改为结构化定位，不再手写 `quote`：

```json
{"evidence_id": "result_...", "path": "/body/current_price", "offset": 0, "length": 240}
```

`offset` 默认0，`length` 默认240，短字段自动取到末尾。JSON Pointer指向规范化结果；字符范围以该字段的JSON序列化内容为准，不是磁盘文件偏移。模型输出Schema将每个证据ID与本次已读状态里的真实路径配对，禁止猜测字段、使用`-1`或省略号代替数组下标。每个证据最多提供128个路径：直接加载字段优先，其余保留前后路径；所需字段未在选项中时可以先用只读工具显式读取，再获得该字段的引用选项。路径枚举仅包含定位信息，不重复展开原文候选。

宿主根据定位提取连续原文，同时证明对应区间已加载，并与授权原始证据逐字比较。短的完整对象字段会自动保留字段名和原始数值格式。不能跨越未读缺口，不能把别名的独立元数据当成另一个ID的已读内容，也不能通过定位还原被安全过滤器隐藏的敏感内容。未读字段返回带ID、路径、offset/limit的补读请求，不消耗格式纠正次数；读取无关字段不会解除该要求。

只有引用真实可读且审核判定通过现有结构、范围、覆盖检查后，才接受结论。已接受的对外审核报告继续保存`evidence_id + quote`，新增`citation_locations`和审计中的`resolved_citations`，以便回查原定位。内部旧调用和已归档重放仍可提交文字引用，但继续执行严格的原文校验；实际模型API不再提供这个分支。

审核结构或判定失败时，审计记录`validation_failures`；最终失败详情同步到审核报告的`error_detail`，避免只保留笼统错误码。未修改模型、调用预算、放行条件或主模型修正闭环。
