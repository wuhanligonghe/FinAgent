## 复用的架构与新增内容

探测复用现有HTTPS白名单校验、请求预算、超时/重试、响应大小限制、原文哈希、获取时间和元数据持久化。仅在独立探测进程中登记以下候选主机，并未修改生产来源配置：

- `79.push2.eastmoney.com`：板块目录、成分股，`api/qt/clist/get`。
- `push2.eastmoney.com`：板块快照，`api/qt/stock/get`。
- `push2his.eastmoney.com`：板块历史日线，`api/qt/stock/kline/get`。

新增可复现脚本：[probe_sector_data.py](../../scripts/probe_sector_data.py)。它分页读取目录，按真实名称/代码匹配板块，校验行情与日线身份，使用现有 `DailyBar` 校验OHLCV，再将规范结果保存为 `Observation`。默认尝试半导体行业和人工智能概念；本次网络波动导致此完整流程未能在线跑通。

```bash
PYTHONPATH=src .venv/bin/python scripts/probe_sector_data.py
```

可通过 `--industry`、`--concept` 指定供应商目录中的精确名称或代码；`--start`、`--end` 指定日线日期；`--output-dir` 指定证据输出目录。脚本在失败时以非零状态退出并保留报告。

另以首轮保存的真实原文做了离线解析检查：银行快照、17条日线、42只成分股均可解析为规范结果；重复第一页会被拒绝，不会把100/496条当作完整目录。此项是解析检查，不是新增的在线成功证据。

## 正式接入需要处理的事项

1. 板块名称、代码、类型应独立于股票标识。目录中“银行”“银行Ⅱ”“股份制银行Ⅲ”等名称同时存在，不能凭旧名称或代码记忆替代解析。
2. 目录和成分股必须分页并校验总数、重复代码。保留供应商分类，当前成分不能用于声称历史成分。
3. 两只板块的快照接口 `f124` 均为0，不能作为有效数据时间。目录中的时间属于另一份快照，应独立注明和引用；获取时间也不能替代行情时间。
4. 价格用指数点，成交量保留供应商定义；源字段涨跌幅应标明来源，程序计算另行复核。
5. 需要新增板块解析、行情、日线和成分股工具适配及来源登记，并验证重试、缓存和故障反馈。现有股票工具不会自动接受 `BK` 代码。

接口分类与字段参考：[AKShare 板块与热度文档](https://akshare.akfamily.xyz/data/stock/stock_board.html)。本次直接请求公开接口，未安装或调用AKShare。
