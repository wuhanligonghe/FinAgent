# 行业排名与数据连接修复

更新日期：2026-11-02。

## 故障不是同一种原因

1. 模型连接修复只配置了 `FINAGENT_MODEL_PROXY`，原金融数据层仍直连。Web 进程没有环境代理时，多家供应商都会出现 `ConnectError`。
2. 原 `get_fund_flow` 是个股资金流，`get_market_attention` 是强势股归因榜，并非行业涨幅榜。缺少个股对象不该误报成日期窗口错误，更不该要求用户选择股票来完成全局行业比较。
3. 东方财富板块接口在当前网络下仍有 `RemoteProtocolError`；代理不能保证修复供应商断连。不能以延长重试或缩短窗口冒充解决。

## 已接入的能力

新增 `get_sector_ranking(limit=10)`，不接受股票代码、基准、任意URL、start/end或历史日期。获取新浪行业汇总，校验字段和代码，再按供应商涨跌幅用 Decimal 排序。最多返回30条。

具体“银行板块”的当天行情可另按[中证银行指数代表口径](INDEX_DATA.md)查询；这与本页全行业排序是不同能力，不会把指数报价冒充新浪行业汇总或全部银行个股。

来源固定为 `https://vip.stock.finance.sina.com.cn/q/view/newSinaHy.php`，沿用受控 HTTPS 主机白名单、请求预算、响应大小限制和原始证据留存。解析数据而不执行返回的 JavaScript；重复键、错位字段、非有限数字和空错误页均拒绝。缺失涨跌幅不按零处理；不能参与排序的行另列原因。

新浪字段口径参考 [AKShare stock_industry.py](https://github.com/akfamily/akshare/blob/main/akshare/stock/stock_industry.py)；本项目直接读取并校验源响应，不安装 AKShare，也不借其包装绕过供应商连接问题。

### 必须保留的限制

- 分类为 `sina_industry`，不等于申万一级、东财行业或题材概念；不混合不同供应商计算一个榜单。
- 该接口没有行情日期或时间。`data_time=null`、`data_time_status=unknown`、`realtime_verified=false`，结果始终是 `partial` 或无可排名项时的 `empty`。
- 获取时间不是行情时间，不能据此声称“今天某行业最强”“实时排名”或“收盘已核验”。可展示的是获取时供应商返回集合的排序参考。
- 涨跌幅是供应商字段，不是本项目重算的行业指数收益；均价单位为元，不是指数点。成交量保留供应商单位。
- 只对该次实际返回的行业集合排序，不证明全市场统一分类覆盖。2026-11-02 实测返回49个行业，但实现不硬编码49。
- 不支持历史、一周/月累计排名、指定行业集合、排除行业或相对基准比较；有这些要求时明确拒绝替代，不静默忽略约束。
- 不支持显式历史截止回填；已声明显式截止的上下文会在联网前拒绝，以免将无时间戳的当前响应填回历史。
- 缓存有效期30秒；刷新失败可返回明确标记 `stale=true` 的旧记录，不更新其获取时间。持续会话中的旧行业证据在30秒后标记失效。

如果业务必须严格回答“某交易日/截至某时刻哪个行业最强”，仍需另接具有可靠行情时间、明确行业层级和可验证历史版本的授权数据源；当前这个公开接口不能消除该缺口。

## 会话交互

全局行业比较直接调用`get_sector_ranking`，不要求公司或基准。独立Task Frame已移除，不再提交`universe`、实体数组或任务版本。主模型根据最新用户原话判断时间、分类和排除要求是否超出工具能力；不得用当前榜单替代不支持的历史或自定义范围。

`get_fund_flow`缺少个股时返回`SYMBOL_REQUIRED`；全局热度与宏观新闻不再因没有股票对象而误报窗口错误。热度榜仍不是行业榜，日期级数据的可用时间规则没有放宽。

## 独立的数据代理

在项目 `.env` 配置实际可用的金融数据代理，并重启后端：

```dotenv
FINAGENT_DATA_PROXY=http://127.0.0.1:17897
```

或在 `finagent.toml` 顶层设置 `data_proxy_url`。它与模型代理独立，默认不自动复用模型代理；没有配置时沿用 HTTPX 环境代理行为。不能通过配置代理绕过执行沙箱或服务商权限。离线测试注入的 HTTP 客户端不会被替换。
