# 记忆机制专项候选评估集 v1

本集覆盖四组指标：检索 Precision/Recall、排序 MRR/NDCG、生成一致性与必要信息覆盖、错误记忆采用率。**48条独立初始化的查询、364条合成种子记忆**，12类场景各4条，开发集24条、留出集24条。它补充整体候选验收集，不复用其中关闭记忆的运行结果。

所有人物、项目、偏好与记录均为合成数据。标签由开发阶段编写，状态为 `developer_candidate_pending_review`；尚未完成独立人工审核，也没有本集的真实模型成绩。结构校验、评分器测试、用金标构造的测试夹具不能作为记忆效果成绩。

## 文件与输入隔离

| 文件 | 内容 | 生成模型可见性 |
| --- | --- | --- |
| `inputs.jsonl` | 查询、当前用户/项目、测试时点、记忆池ID、初始化事件、集合与类别 | 只传query和必要运行上下文；不传类别、集合、case_id等评估元数据 |
| `memories.jsonl` | 不带相关度标签的种子记忆正文、类型、常驻标记、时间、归属与来源 | 通过真实记忆流程筛选后，只提供实际注入的记录；不整池拼进提示词 |
| `gold.jsonl` | 逐条相关度、回答检查项、错误采用规则、标注说明 | 不可见，仅评分器和审核者读取 |
| `protocol.json` | 四组指标定义、计分口径、边界 | 不作为生成模型上下文 |
| `schemas.json` | 记忆、输入、标签、预测与答案审核的JSON Schema | 供适配器/评分器校验 |
| `manifest.json` | 冻结文件SHA256与规模 | 绑定本版数据，摘要应另行保管 |

记忆ID与来源ID为不含答案标签的稳定不透明标识；记忆池顺序确定性打乱。源记忆中的“后来更正”“仅10月适用”“未经用户确认”等内容属于原始来源语义，不是偷偷提供的评分标签。

## 场景

1. 语义召回：查询与记忆不必逐字重合。
2. 多条记忆组合：格式、金额单位、项目读者和可选背景同时存在，并标分级相关度。
3. 偏好更正：采用最新有效值，允许解释旧值曾经存在。
4. 时效：按2026-11-05的冻结时点区分10月临时规则与11月规则。
5. 当前指令覆盖：本轮要求优先，不把一次覆盖误写成永久偏好更新。
6. 用户隔离：其他账号的相似偏好不能归给当前用户。
7. 项目隔离：同一账号的另一个项目技术栈不能串入当前项目。
8. 删除：回放forget后不从旧记录、摘要或索引恢复已删除偏好。
9. 无相关记忆：信息不足时说明未知，不用相似但不等价的偏好代替。
10. 常驻偏好：全局表达偏好跨会话、跨项目保持有效。
11. 历史追问：旧值和新值都可能相关，按历史角色正确使用不算错误。
12. 来源优先级：用户明确确认的偏好优先于助手未确认的推测。

按合成用户、项目和profile场景组隔离开发/留出集合；同一用户的全部场景留在同一集合。四个profile不构成48个独立用户。场景类型、部分写作模板跨集合，**不声称语义独立、秘密留出或统计充分性**。本版由作者可见，正式独立验收仍需另行审核与数据治理。

## 四组指标的计算口径

### 1. 检索Precision/Recall

相关度0=无关或本任务不可用，1=有帮助的背景，2=重要补充，3=回答必需。二值相关性取grade>0。

`retrieved_ids`是检索器经过重排、阈值和自身限额后实际返回的非core记忆，按实际顺序记录。不要混入常驻core记忆，不要在评分前剔除错误用户/项目等坏结果；这些结果须作为错误检索被计分。`core_ids`单独记录，实际送给模型的合并上下文用`injected_ids`记录。

- 取k=1/3/5。Precision为前至多k条中相关条数/实际返回条数，明确不是固定用k作分母的另一种P@k口径；自适应检索无需用无关记录凑满k。
- Recall为命中的相关非core记忆数/全部相关非core记忆数。
- 正样例没有返回记忆，Precision与Recall记0。
- 无相关非core记忆的样例，Recall标null；若未返回，Precision也为null，若返回无关条目则Precision为0。另报空gold查询误检率，不把正确空召回当成1分来抬高平均值。
- 常驻偏好不作为检索排序对象；漏注入或错误使用常驻偏好由生成检查体现。常驻专用题的检索Recall/MRR/NDCG可为null。

### 2. 排序MRR/NDCG

MRR@k为前k条中首个相关结果的倒数排名。NDCG@k使用`2^grade-1`作为增益、`log2(rank+1)`作为折扣，理想顺序来自该题相关度标注。MRR衡量首个相关结果的位置；分级重要性由NDCG体现。空相关集合均标null，不补成满分。

### 3. 生成一致性

分别报告两个分数，避免空泛回答或仅复述一条记忆获得满分：

- `memory_claim_support_rate`：已审核的记忆依赖主张中，得到实际注入且适用的记忆支持的比例。矛盾和无法核验都进入分母，没有此类主张时为null。
- `required_information_coverage`：gold中必须体现的行为/信息检查项通过数/完整检查项数。明确单位、过去/现在、表达顺序、应当拒绝猜测等都可以是检查项；记忆来源检查通过还必须有相应记忆实际注入。

生成部分使用独立的逐答案审核，或另行验证的语义评审器。不能只用字符串重合、引用ID、ROUGE或Qwen的主张提取结果自动认定“正确使用记忆”。纯格式偏好可用答复结构和实际段落作为审核依据；这类行为不必伪装成文字中的事实主张。

### 4. 错误记忆采用率

按答案计数：已审核回答中，至少出现一次gold定义的错误采用行为的回答数/已审核回答数；同时单列错误探针子集上的比例。错误行为必须绑定预先定义的规则、实际注入的记忆ID和答案中的逐字引文。

例如，将“以前用万元”写成“现在默认万元”算错；正确解释“以前万元，现在亿元”不算错。其他用户/项目、删除记录、已失效约定、未经确认的推测都包含专门规则。正确记忆也可能被误读成相反的时间角色，因此规则不只是一个静态的坏ID列表。

这是**可观察的错误内容采用率**，不是因果影响估计。未注入某条记忆时，不能仅因答案恰好相似就说它使用了那条记忆；这类捏造可在一致性审核中标为无法核验。失败/取消数量和完整覆盖率必须一起展示，不能把低错误采用率单独当成系统通过验收。

## 运行约定

每题创建独立临时数据根目录和新会话，按corpus_ids装载本题种子记录。保留user_id/project_id、core、created_at和来源；其他用户/项目的记录放在其真实归属范围内，不能先按gold过滤后冒充隔离成功。测试数据不写入真实用户记忆目录。

`setup_events`是初始化时要实际回放的宿主操作：例如写入后调用forget，再开始查询；不要给模型展示被删除的正文。若真实运行产生新UUID，适配器需保留“实际ID→数据集不透明ID”映射供评分。查询与记忆正文可以提供给模型，gold及其相关度、requirements、invalid_use_rules不可提供。

实际启用记忆；记录运行配置、代码摘要、模型、数据manifest摘要、检索顺序、常驻记录和**真正进入模型请求的memories**。injected_ids不是全部候选池，也不是尚未过滤的检索中间结果。本数据集暂不附带连接生产会话的自动模型运行器；评分脚本只消费真实记录，避免把现有关闭记忆的整体验收链路直接当成记忆评估。

离线校验（不调用模型）：

```bash
.venv/bin/python scripts/evaluate_memory_benchmark.py validate
```

生成运行记录的JSONL，每行符合`schemas.json`中的prediction，例如：

```json
{"id":"mv1_025","dataset_manifest_sha256":"填写本次运行前manifest.json的64位SHA256","memory_enabled":true,"retrieved_ids":[],"core_ids":[],"injected_ids":[],"status":"completed","answer":"实际生成的答复"}
```

上面只演示格式，摘要占位符须替换为实际值，不是有效模型成绩或标准答案。每行绑定运行前的manifest摘要，改动数据后不能沿用旧版本预测。运行失败/取消也保留一行并记录真实状态。评分时不允许跨集合预测、重复ID、未知记忆ID、关闭记忆或伪造注入来源。

```bash
.venv/bin/python scripts/evaluate_memory_benchmark.py score --split development \
  --predictions /path/to/predictions.jsonl --output .finagent/memory_eval/development.json
```

没有逐答案审核时，只报告检索和排序，生成指标为null且状态为not_evaluated。缺失的正样例按召回/排序0计分，并完整列出missing，不从分母删除。报告不会自动宣称独立验收通过。

逐答案审核文件符合`schemas.json`的review：写审核者、带时区时间、是否独立于标签编写；每题绑定实际answer的SHA256，完整填写requirements、memory_claims和invalid_uses。通过项必须给出实际答复引文；不通过项可以用空引文说明缺失。无错误采用时列表为空，不应省略对照审核。格式校验不能证明审核者身份或判断正确，审核记录应另行保存。

```bash
.venv/bin/python scripts/evaluate_memory_benchmark.py score --split holdout \
  --predictions /path/to/predictions.jsonl --review /path/to/answer_review.json \
  --output .finagent/memory_eval/holdout.json
```

评分器始终报告planned/predicted/reviewed/missing及失败数量。人工审核不全时生成状态为partial，不能把局部值称为整个留出集成绩。候选数据没有预设未经验证的上线阈值。

## 修改与复核

作者源文件为`scripts/build_memory_benchmark.py`，固定时点和内容保证本环境下可重建。修改候选标签后重新生成、校验并更新冻结摘要；独立审核后需要另建新版本，不能沿用旧审核和旧分数。

```bash
.venv/bin/python scripts/build_memory_benchmark.py --overwrite-candidate
.venv/bin/python -m unittest tests.test_memory_benchmark -v
```

建议独立审核者逐题核对：范围归属、时间/更正优先级、相关度分级、必需信息是否确实必需、错误采用条件，以及空召回/拒绝猜测是否合理。任何拒绝标签都应修订并重新冻结；本次不会自动填入独立批准。
